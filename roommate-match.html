Roommate-Match

Roommate matching with Irving’s Stable Roommates algorithm, checked against a brute-force oracle.

  • Node.js / Express
  • React
  • PostgreSQL
  • Redis
  • Socket.io
  • Jest
Source on GitHub ↗Differential test ↗

No hosted demo. Reproducible example below: run the test suite.

Problem
Roommates form one pool, not two sides, so Gale–Shapley does not apply. Some pools have no stable matching.
What I owned
Solo project. An Express and React app with JWT cookie auth, Postgres, Redis presence, and Socket.io chat. I implemented Irving’s algorithm and wrote the tests.
Result
38 tests pass. Irving’s output agrees with a brute-force oracle on 10,500 seeded random instances. Chat module coverage: 100% statements, 97.2% branches.

Reproducible example

Run it yourself

Key decision

Use Irving’s algorithm. Prove it with differential testing.

Why
Rotation elimination is easy to get wrong. The test enumerates every perfect matching for small pools, checks stability directly, and compares the verdict. The generator is seeded, so failures replay.
Trade-off
With no stable matching, the app pairs greedily by compatibility, which is neither stable nor optimal. The oracle only scales to 10 people. Ties fall back to database row order.

Evidence: stableRoommates.js and pull request #1, the rewrite.
